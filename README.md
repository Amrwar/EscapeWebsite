# Escape Barbershop — Website

A site for Escape Barbershop in Mivida, New Cairo. Twelve pages on bone paper with ink type, dropping into dark bands for the hero, the film strip and the footer — bright like the shop itself, with the colour coming from the photography. Live "open now" pill, searchable service menu, photo lightbox, silent clips filmed in the chairs, and a booking form that sends requests to the shop's WhatsApp.

**Live:** https://escape-website-phi.vercel.app — every push to `main` redeploys it.

---

## The one file you'll actually edit

Everything the site says about the shop — phone, WhatsApp, email, address, hours, the full service menu, packages, the team, the FAQ, reviews — lives in **`site.config.json`**.

Change it, run `npm run build`, and every page that shows that information updates. You never edit the same phone number in twelve places.

```bash
npm install     # once
npm run build   # rebuild the pages after editing site.config.json
npm run dev     # build, then serve on http://localhost:8000
npm run images  # make WebP copies of new photos (needs ffmpeg)
```

The build prints a warning listing anything still on a placeholder value.

### Still to fill in

| In `site.config.json` | What to do |
|---|---|
| `phoneDisplay` / `phoneHref` / `whatsapp` | Replace `+20 100 000 0000` with the shop's real number. `whatsapp` is digits only, with country code, no `+` (e.g. `201001234567`). |
| `email` | Currently a placeholder address. |
| `social.instagram` / `tiktok` / `facebook` | Empty for now, so no icons appear. Paste the profile URLs in and the icons show up in every footer and on the Contact page. |
| `services[].price`, `packages[].price` | All `null`. While every price is null the menu shows durations only — as soon as one is filled, a price column appears everywhere. |
| `team` | The four names came from the shop's own booking system. Check them and what each is known for. Photos are automatic — see below. |
| `reviews` | Empty on purpose — the Reviews page invites people to Google rather than showing anything made up. Add real ones as `{ "quote", "author", "source", "rating" }`. |
| `url` | Set this to the final domain once there is one, so the social cards and sitemap point at the right place. |

## How the booking form works

The form doesn't pretend to book anything by itself. It validates what was typed — including refusing a time when the shop is shut that day — writes the request out in full, and hands it to WhatsApp (or SMS, or the clipboard). The visitor presses send, and it lands in the shop's normal WhatsApp chat.

That means: **nothing is booked until the shop replies**, and the page says so.

### Blocking out times that are already taken

Picking a barber and a date shows half-hour slots instead of a plain time field, and any exact slot already requested with that same barber is greyed out. This only tracks requests made through this form — it still doesn't know about anything arranged by phone or WhatsApp directly, and "no preference" bookings aren't tracked either, since there's no specific chair to check against.

This needs a one-time setup that isn't done automatically:

1. In the Vercel dashboard, open this project → **Storage** → **Create Database** → **Marketplace Database Providers** → pick a **Redis** option (Upstash). Connect it to this project — Vercel adds the required environment variables on its own.
2. Redeploy once after connecting it.

Two small serverless functions live in `api/` (`slots.mjs` reads what's taken, `book.mjs` reserves a slot) — nothing else to configure. Until the storage is connected, both quietly fall back to showing every time as open (the same as before this feature existed) rather than breaking.

## Structure

```
site.config.json    — the shop's details: the file to edit
api/slots.mjs       — serverless: what's already booked for a barber/date
api/book.mjs        — serverless: reserves a slot
api/_redis.mjs      — shared Redis client for both of the above
src/pages/*.mjs     — one file per page, its own content only
src/script.ts       — all the interactive behaviour (compiled to js/script.js)
tools/layout.mjs    — the shell every page shares: head, header, footer, action bar
tools/components.mjs— blocks used on more than one page (menu, hours, FAQ, team…)
tools/build.mjs     — pours pages into the shell, writes the HTML + sitemap
tools/photos.mjs    — finds photos dropped into images/team and images/gallery
tools/optimize-images.mjs — makes the WebP copies the pages serve first
tools/serve.mjs     — the local preview server
tools/smoke.mjs     — end-to-end checks (see below)
css/style.css       — the whole design system
images/team/        — barber portraits, picked up by file name
images/gallery/     — gallery photos, filed by the folder they're in
images/, videos/    — logo, favicon, the photos that shipped, optional hero clip
*.html              — generated. Don't edit these by hand; they're overwritten.
```

Adding a page means adding one file to `src/pages/` and, if it belongs in the nav, one line in `NAV` (or `NAV_SECONDARY`) in `tools/layout.mjs`.

## What else is on the site

- **The film strip** — four silent clips shot in the shop (a cut, a treatment, the chair, pulling up at Gate 2). They load and play only while on screen, so the page stays light for anyone who doesn't scroll that far.
- **Booking** — the fields are grouped the way you'd be asked in person (who you are, what you're after, when), with a card beside them that fills in as you type so the request is readable before it's sent.
- **Booking extras** — the form remembers your name and number on your own device, and offers an **Add to My Calendar** file (marked tentative, since the shop still confirms). After hours it says so instead of letting you wonder.
- **Print the Menu** — a print stylesheet turns the services page into a clean list on white paper.
- **Home-screen install** — `site.webmanifest` is generated at build time, so the site can be saved to a phone's home screen.
- **Tidy URLs** — `vercel.json` redirects `/barbers`, `/team`, `/booking`, `/prices` and `/menu` to the right pages, and keeps the old `/barbers.html` link working.

## Testing

```bash
npm run dev                                    # terminal 1
chrome --headless --remote-debugging-port=9222 # terminal 2
node tools/smoke.mjs                           # terminal 3
```

Drives a real headless Chrome through 20 checks: the menu filter and search (including Arabic), the gallery lightbox and its keyboard controls, the FAQ accordion, the team cards and their photo fallback, and the booking form — that it pre-fills from a deep link, rejects an empty name and a closed-hours time, builds the right message, remembers the customer, and writes a calendar file covering the right slot.

## Adding photos

You never edit code to add a picture. Drop the file in the right folder and run `npm run build`.

**Barber portraits** → `images/team/<name>.jpg`, named after the barber in lowercase (`images/team/khaled.jpg`). It appears on their card everywhere they're shown. Until then the card shows a monogram plate, which is why nothing looks half-built while we wait. Upright, roughly 3:4, about 1200px on the long edge.

**Gallery photos** → `images/gallery/<section>/<file>.jpg`. The folder name becomes the filter button on the Gallery page (`images/gallery/the-chairs/mirrors.jpg` files it under "The Chairs"), and new photos also feed the three tiles on the home page. The file name becomes the alt text; to write your own, add it to `photoCaptions` in `site.config.json`. Landscape, about 1600px wide.

Both folders have a README repeating this, so it's there when you need it.

After adding photos run `npm run images`. It writes a WebP copy next to each one — about 40% smaller — and the build serves that first with the original as the fallback, so nothing breaks on an older browser. It only touches photos whose copy is missing or out of date, and it needs ffmpeg (`npm i -D ffmpeg-static` is enough).

Everything is rendered in black and white to match the rest of the site, so don't worry about matching colour between shots.

### What's in there now

Nine photos of the shop (`images/gallery/the-shop`, `the-chairs`, `details`), the four barber portraits (`images/team/barber-1..4.jpg`), and the five older photos that came with the first version (`images/*.jpg`).

**Videos** — `videos/hero.mp4` plays behind the home hero; `reel-cut`, `reel-treatment`, `reel-chair` and `reel-arrival` make up the film strip. All silent, all cut down from the originals to about 0.4–1.3 MB each, each with a poster frame beside it. To swap one, drop a new file in with the same name — or re-cut from a source clip:

```bash
ffmpeg -ss 2 -t 8 -i source.mp4 -an -vf "scale=540:960:flags=lanczos"   -c:v libx264 -preset slow -crf 29 -pix_fmt yuv420p -movflags +faststart videos/reel-cut.mp4
ffmpeg -ss 2 -i source.mp4 -frames:v 1 -vf "scale=540:-2" -q:v 5 videos/reel-cut-poster.jpg
```

Remove `videos/hero.mp4` and the hero falls back to a photo on its own.

**Logo** — `images/logo.png`, used in the header, hero and footer. `images/favicon.svg` is the browser-tab icon.

## Design notes

- **Type** — Fraunces (serif) for headings, Inter for everything else.
- **Palette** — bone paper (`#f7f5f0`) and ink (`#15140f`), with dark bands for the hero, film strip, call-outs and footer. Any section can carry `theme-dark` or `theme-light`; both set the same handful of variables, and every component is written against those. Tokens live at the top of `css/style.css`.
- **Photos** are shown in colour, as shot — they're where the warmth comes from.
- **Signature pieces** — the photo collage on the home page, the overlapped photo stack in the story section, the section rail down the left edge, and the preview image that follows the cursor across the service menu (desktop, pointer devices only).
- **Motion** — scroll reveals, count-ups, a marquee and a hero glow, all disabled for anyone who asks for reduced motion.
- **Accessibility** — skip link, visible focus rings, labelled controls, keyboard-operable lightbox and accordion, and the nav collapses to a full-screen menu below 1100px.
