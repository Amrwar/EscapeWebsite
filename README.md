# Escape Barbershop — Website

A dark, upscale site for Escape Barbershop in Mivida, New Cairo. Twelve pages, monochrome to match the shop's logo and photography, with a live "open now" pill, a searchable service menu, a photo lightbox and a booking form that sends requests to the shop's WhatsApp.

**Live:** https://escape-website-phi.vercel.app — every push to `main` redeploys it.

---

## The one file you'll actually edit

Everything the site says about the shop — phone, WhatsApp, email, address, hours, the full service menu, packages, the team, the FAQ, reviews — lives in **`site.config.json`**.

Change it, run `npm run build`, and every page that shows that information updates. You never edit the same phone number in twelve places.

```bash
npm install     # once
npm run build   # rebuild the pages after editing site.config.json
npm run dev     # build, then serve on http://localhost:8000
```

The build prints a warning listing anything still on a placeholder value.

### Still to fill in

| In `site.config.json` | What to do |
|---|---|
| `phoneDisplay` / `phoneHref` / `whatsapp` | Replace `+20 100 000 0000` with the shop's real number. `whatsapp` is digits only, with country code, no `+` (e.g. `201001234567`). |
| `email` | Currently a placeholder address. |
| `social.instagram` / `tiktok` / `facebook` | Empty for now, so no icons appear. Paste the profile URLs in and the icons show up in every footer and on the Contact page. |
| `services[].price`, `packages[].price` | All `null`. While every price is null the menu shows durations only — as soon as one is filled, a price column appears everywhere. |
| `team` | The four names came from the shop's own booking system. Check them, and drop photos into `images/team/` and set `photo` on each. |
| `reviews` | Empty on purpose — the Reviews page invites people to Google rather than showing anything made up. Add real ones as `{ "quote", "author", "source", "rating" }`. |
| `url` | Set this to the final domain once there is one, so the social cards and sitemap point at the right place. |

## How the booking form works

There's no server behind this site, so the form doesn't pretend to send anything by itself. It validates what was typed — including refusing a time when the shop is shut that day — writes the request out in full, and hands it to WhatsApp (or SMS, or the clipboard). The visitor presses send, and it lands in the shop's normal WhatsApp chat.

That means: **nothing is booked until the shop replies**, and the page says so.

## Structure

```
site.config.json    — the shop's details: the file to edit
src/pages/*.mjs     — one file per page, its own content only
src/script.ts       — all the interactive behaviour (compiled to js/script.js)
tools/layout.mjs    — the shell every page shares: head, header, footer, action bar
tools/components.mjs— blocks used on more than one page (menu, hours, FAQ, team…)
tools/build.mjs     — pours pages into the shell, writes the HTML + sitemap
tools/serve.mjs     — the local preview server
tools/smoke.mjs     — end-to-end checks (see below)
css/style.css       — the whole design system
images/, videos/    — photos, logo, favicon, optional hero clip
*.html              — generated. Don't edit these by hand; they're overwritten.
```

Adding a page means adding one file to `src/pages/` and, if it belongs in the nav, one line in `NAV` (or `NAV_SECONDARY`) in `tools/layout.mjs`.

## Testing

```bash
npm run dev                                    # terminal 1
chrome --headless --remote-debugging-port=9222 # terminal 2
node tools/smoke.mjs                           # terminal 3
```

Drives a real headless Chrome and checks the menu filter and search (including Arabic), the gallery lightbox and its keyboard controls, the FAQ accordion, and the booking form — that it pre-fills from a deep link, rejects an empty name and a closed-hours time, and builds the right message.

## Design notes

- **Type** — Fraunces (serif) for headings, Inter for everything else.
- **Palette** — true monochrome: near-black backgrounds, off-white text, one hairline border colour. Tokens live at the top of `css/style.css`.
- **Photos** are rendered greyscale so mixed-quality sources read as one set.
- **Motion** — scroll reveals, count-ups, a marquee and a hero glow, all disabled for anyone who asks for reduced motion.
- **Accessibility** — skip link, visible focus rings, labelled controls, keyboard-operable lightbox and accordion, and the nav collapses to a full-screen menu below 1100px.
